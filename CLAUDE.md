# CDDA Multiplayer — форк Cataclysm: Dark Days Ahead

Этот файл — рабочая память проекта. Читай его в начале каждой сессии. Обновляй разделы «Статус» и «Журнал решений» после каждого завершённого шага.

## Цель

Кооператив на двоих (потом, возможно, больше) в оригинальной CDDA. Хост играет обычным аватаром, второй игрок подключается по сети и управляет своим персонажем.

## Базовая версия

* Снимок исходников стабильного тега `0.I-1` (апстрим CleverRaven/Cataclysm-DDA, коммит `7b2efa5cea38e4d4d97dd0e63b28b9148623da59`), не master/experimental.
* Апстрим не догоняем. Переход на новую стабильную версию — отдельное решение.
* Репозиторий: `zombo658/cataclysm-dda-mp`. История апстрима не импортирована. Сравнить с оригиналом:
  `git fetch --depth 1 https://github.com/CleverRaven/Cataclysm-DDA.git tag 0.I-1` и `git diff 0.I-1 HEAD`.

## Архитектура (принятое решение)

Второй игрок — это NPC, у которого вместо ИИ очередь команд из сети.

* Аватар и NPC наследуются от `Character`, поэтому у NPC уже есть всё: инвентарь, здоровье, навыки, сохранение, участие в цикле ходов.
* Вводим «удалённо управляемого NPC» (remote-controlled NPC, далее RC-NPC). Когда у RC-NPC есть очки ходов, он берёт команду из очереди вместо ИИ.
* Если у RC-NPC есть ходы, а очередь пуста, мир ставится на паузу и ждёт. Это и есть синхронизация времени.
* Сервер авторитарный: вся симуляция идёт только в процессе хоста.
* Пузырь реальности остаётся центрированным на аватаре хоста. На первых этапах RC-NPC запрещено уходить за его пределы.
* Сетевой протокол: TCP, JSON по одному объекту на строку (NDJSON), порт 7777.
* Клиент второго игрока пишется на Python, отдельно от игры.

Подробный разбор кода — `docs/mp/architecture-notes.md`.

## Ключевые места в коде (проверено на 0.I-1)

* `src/do_turn.cpp` — `bool do_turn()`, главный цикл хода; `monmove()` (монстры, затем NPC).
* `src/handle_action.cpp` — `game::handle_action()`, ввод игрока → действие.
* `src/npcmove.cpp` — `npc::move()` (решение ИИ на ход, стр. 1334) и `npc::execute_action( npc_action )` (стр. 1608). Сюда встраивается очередь RC-NPC.
* `src/npc.h`, `src/npc.cpp` — класс NPC.
* `src/avatar.h` — `get_avatar()`, синглтон игрока. Много кода завязано на него.
* `src/character.h` — общий базовый класс персонажей. Ходы начисляются в `Character::process_turn()` (`src/character.cpp:2418`).
* `src/debug_menu.cpp` — `control_npc_menu()` → `avatar::control_npc()` (`src/avatar.cpp:156`). Пример переключения управления, полезен для отладки.
* `src/map.h`, `src/map.cpp` — карта и пузырь реальности.
* `src/input.h`, `src/input.cpp` — контексты ввода.
* `src/savegame_json.cpp` — `npc::load` (стр. 2074) / `npc::store` (стр. 2290).

## Правила работы

1. Маленькие шаги. Одна задача — один рабочий результат — один коммит.
2. Минимум изменений в ядре. Новый код кладём в `src/mp/`. В существующие файлы добавляем только тонкие хуки (вызов функции из `src/mp/`), чтобы патч оставался читаемым и его можно было перенести на другую версию.
3. Не трогаем JSON-контент в `data/` без явной необходимости.
4. Сначала понять, потом менять. Прежде чем править чужой код, прочитай, кто ещё его вызывает. Если фикс — костыль, так и скажи.
5. Всё должно собираться перед коммитом. Сломанную сборку не коммитим.
6. Пишем в стиле проекта (см. `.astylerc`, `doc/` по стилю кода).
7. Если решение по дизайну неочевидно — не выбирай сам молча, предложи варианты и спроси.

## Сборка

Отладочная curses-сборка (проверено в облачном контейнере, Ubuntu, g++, 4 ядра). Нужны `g++`, `make`, `libncurses-dev`.

```
make -j$(nproc) RELEASE=0 TILES=0 SOUND=0 LOCALIZE=0 ASTYLE=0 LINTJSON=0 BACKTRACE=0 cataclysm
```

* Полная сборка — около 13–15 минут на 4 ядрах. Пересборка после правки одного `.cpp` — около минуты.
* Файлы `src/mp/*.cpp` Makefile подхватит, только если добавить каталог в его список исходников — сделать при первом файле в `src/mp/`.
* Сборка с `-Werror`: любое предупреждение ломает её.

Запуск (игре нужна UTF-8 локаль):

```
LANG=C.UTF-8 LC_ALL=C.UTF-8 ./cataclysm --userdir ../cdda-userdir/
```

Проверка без экрана: запустить в `tmux new-session -d -x 200 -y 60`, слать клавиши `tmux send-keys`, смотреть `tmux capture-pane -p`.

Форматирование: в контейнере нет `astyle`. Если появится — `astyle --options=.astylerc` на изменённых файлах перед коммитом.

## Журнал решений

* Выбран форк оригинала, а не переписывание с нуля.
* Второй игрок реализуется как NPC с сетевой очередью команд.
* База — стабильный тег `0.I-1`.
* Отдельный репозиторий `zombo658/cataclysm-dda-mp`; снимок исходников одним коммитом без истории апстрима (полная история весит несколько ГБ, апстрим не догоняем).
* Хук RC-NPC ставится в начало `npc::move()`; пауза не может быть «выходом без траты ходов» — через 10 таких выходов `monmove()` вызывает `npc::reboot()` (NPC «падает в обморок»).
